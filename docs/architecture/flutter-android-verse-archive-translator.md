# Flutter Android VerseArchiveTranslator Architecture

## Goal

The Flutter Android app mirrors the existing desktop `VerseArchiveTranslator` workflow while adapting the interaction model for phone screens and Android file access.

The architecture stays split into four layers:

- UI
- controller
- repository
- storage bridge

Repository and data semantics remain aligned with the desktop implementation. The phone-specific changes live primarily in the UI and Android storage bridge.

## Main modules

- `apps/verse_archive_translator_flutter/lib/src/ui/home_page.dart`
- `apps/verse_archive_translator_flutter/lib/src/controllers/translator_controller.dart`
- `apps/verse_archive_translator_flutter/lib/src/services/archive_repository.dart`
- `apps/verse_archive_translator_flutter/lib/src/storage/workspace_storage.dart`
- `apps/verse_archive_translator_flutter/android/app/src/main/kotlin/com/versearchive/verse_archive_translator_flutter/MainActivity.kt`

## Mobile UI information architecture

### AppBar

The AppBar now carries the high-frequency workspace actions:

- open folder
- recent workspaces
- workspace info
- reload
- save

This keeps the main phone screen focused on translation work instead of persistent workspace metadata.

### Workspace details

Workspace details are intentionally removed from the main working surface.

They now live in a bottom sheet and include:

- workspace name
- archive root
- resolution source
- tree URI
- full-library stats
- resolution notes

### List tab

The list tab is structured as:

1. Search
2. Type filter and random scope filter
3. Compact visible-results summary
4. Result list

The summary is computed from the visible list only:

- visible list = `search query + type filter`
- summary = counts over visible list
- random scope filter does not affect visible list or summary

### Edit tab

The edit tab is structured as:

1. Compact record header
2. Source section
3. Translation section
4. Expandable metadata section
5. Low-height sync / save bar

The source and translation section cards also support long press copy. Clipboard text is generated by a pure formatter so the UI interaction can stay thin and the text format can be unit-tested without clipboard side effects.

This reduces header density and preserves more vertical space for reading source text and typing translation text.

## Keyboard handling strategy

Phone editing now uses these layout rules:

- `Scaffold.resizeToAvoidBottomInset = true`
- editor content inside a scrollable area
- `Scrollable.ensureVisible` when translation fields receive focus
- bottom padding inside the editor scroll area
- bottom navigation hidden while keyboard is open

This resolves the previous in-device overflow and keyboard-covering issues without changing repository behavior or save semantics.

## Semantics intentionally unchanged

This UI pass does not change:

- JSON schema
- archive loading and saving logic
- translation-state logic
- search semantics
- random-pick semantics
- save-field rules

All of those remain controlled by the repository and model layer.
